# بين الرسائل – Between Letters

تطبيق ويب متكامل (Responsive PWA) للمراسلات الرومانسية الخاصة لشخصين فقط، مستوحى من مراسلات القرن التاسع عشر وفلسفة **«فن انتظار الرسائل – The Art of Waiting»**.

---

## ١. البنية التقنية ولماذا تم اختيارها

يعتمد المشروع على:
- **Frontend & Backend:** Next.js (App Router) + React + TypeScript + Tailwind CSS
- **قاعدة البيانات:** PostgreSQL عبر Drizzle ORM
- **المصادقة:** جلسات HTTP-Only JWT موقّعة (`jose`) مع تجزئة كلمات المرور عبر `bcryptjs`
- **الإشعارات:** قاعدة بيانات الإشعارات المخصّصة + Web Push Notifications (`web-push`) + Service Worker (`/sw.js`)
- **الخطوط:** 18 خطاً عربياً ولاتينياً مفتوح المصدر محمّلة ذاتياً عبر `next/font/google`

### سبب اختيار Next.js + PostgreSQL بدلاً من Firebase
1. **توقيت الخادم الموثوق (Server-Authoritative Clock):** متطلب أساسي ألا يقرأ المستلم الرسالة قبل موعد وصولها حتى لو غيّر ساعة هاتفه. في هذه البنية، تتحقق قاعدة البيانات وخادم Next.js من `NOW() >= delivery_at` قبل إعادة حقل `content` أو `handwritingImage` من الأصل.
2. **صلاحيات صارمة لشخصين فقط على مستوى قاعدة البيانات:** تضمن المعاملات الذرية (Database Transactions) في PostgreSQL استحالة انضمام حساب ثالث لنفس العلاقة، ومنع تعديل أي رسالة بعد إرسالها.
3. **تشغيل مجاني بالكامل دون قيود خطط السحابة:** يمكن استضافته مجاناً أو بتكلفة منخفضة على أي خادم يدعم Node.js وPostgreSQL دون الخوف من حدود القراءة/الكتابة في Firebase Spark أو الحاجة لبطاقة ائتمان لتفعيل Cloud Functions (Blaze Plan).

> **ملاحظة حول التكاليف المحتملة والحدود:**
> - **الاستضافة وPostgreSQL:** توجد خطط مجانية (مثل Supabase / Neon / Railway / Render) بحدود مساحة قاعدة بيانات مجانية (عادة 500MB–1GB)، وهي تكفي لآلاف الرسائل النصية، بينما تخزين الصور اليدوية عالية الدقة بكثرة قد يستهلك المساحة بشكل أسرع.
> - **خدمة Web Push:** مجانية تماماً ولا تتطلب مفاتيح Firebase مدفوعة، وتعتمد فقط على توليد مفاتيح VAPID مجاناً.

## ٢. الميزات المنفذة

- **حسابات وخصوصية صارمة:** تسجيل، دخول، استعادة كلمة المرور، اسم مستعار، صورة شخصية (PNG/JPEG/WebP بحد أقصى 750KB)، وربط الحسابين برمز دعوة فريد (`BL-XXXX-XXXX`) يُغلق نهائياً بعد انضمام الشريك.
- **الصفحة الرئيسية (المكتب وصندوق البريد):** مكتب خشبي كلاسيكي، صندوق بريد مرئي يتفاعل عند وصول رسائل جديدة دون كشف محتواها.
- **محرر الرسائل المتكامل (`/compose`):**
  - 7 تصاميم ورقية مع معاينة حية.
  - 18 خطاً مصنفة: عربية كلاسيكية (`Amiri`, `Aref Ruqaa`, `Noto Naskh Arabic`, `Lateef`, `Gulzar`)، عربية عصرية (`Cairo`, `Tajawal`, `Reem Kufi`, `IBM Plex Sans Arabic`)، خطوط تحاكي الكتابة اليدوية (`Playpen Sans Arabic`, `Vibes`, `Harmattan`)، وخطوط إنجليزية وفرنسية (`Caveat`, `Dancing Script`, `Great Vibes`, `Parisienne`, `Cormorant Garamond`, `Libre Baskerville`).
  - دعم كامل للتشكيل العربي، واتجاه النص التلقائي/اليدوي (`RTL` / `LTR`) المستقل عن لغة الواجهة.
  - حفظ تلقائي للمسودات في قاعدة البيانات و`localStorage` لمنع فقدان النص عند تحديث الصفحة.
  - **لوحة الكتابة اليدوية باللمس أو الفأرة:** قلم حبر، تغيير السمك، اختيار لون الحبر، تراجع، مسح، إعادة المحاولة، وحفظ كصورة PNG عالية الدقة.
- **الأظرف والطوابع والأختام الشمعية:** 6 تصاميم أظرف، 8 طوابع بريدية Vintage، و8 أختام شمعية برسومات (قلب، زهرة، نجمة، هلال، تاج).
- **نظام التوصيل والانتظار والمجدولة:**
  - توصيل فوري أو بعد (5 دقائق، 30 دقيقة، ساعة، 6 ساعات، 12 ساعة، 24 ساعة، أو تاريخ مخصص).
  - **رسالة مرسلة مؤجلة الوصول:** تُرسل فوراً لكنها تبقى مقفلة في الخادم حتى يحين موعدها.
  - **رسالة مجدولة للإرسال:** تبقى في جدول المسودات ولا تغادر نحو البريد إلا عند حلول موعد إرسالها على الخادم.
- **تجربة فتح الرسالة (`/letters/[id]`):** فضّ الختم الشمعي بحركة ناعمة، فتح الظرف، وانفراد الورقة بخطها الأصلي مع مؤثرات صوتية اختيارية عبر Web Audio API.
- **البريد الوارد والصادر وأرشيف الذكريات:** بحث، تصفية حسب المرسل والتاريخ والمفضلة، وتصدير نسخة احتياطية كاملة بصيغة JSON (`/api/archive/export`).
- **دعم 3 لغات:** العربية (افتراضية RTL)، الفرنسية (LTR)، والإنجليزية (LTR).

## ٣. متطلبات الإشعارات (Web Push & HTTPS) وقيود الهواتف

1. **شرط HTTPS:** إشعارات المتصفح والـ Service Worker لا تعمل في الإنتاج إلا عبر **HTTPS** (باستثناء `localhost` أثناء التطوير).
2. **قيود iOS / iPhone / iPad:** تدعم Apple إشعارات Web Push منذ **iOS 16.4+**، ولكن يشترط أن يقوم المستخدم بـ **تثبيت التطبيق على الشاشة الرئيسية (Add to Home Screen)** عبر Safari ثم تفعيل الإشعارات من صفحة الإعدادات داخل التطبيق المثبّت.
3. **إخفاء المحتوى:** لا تحتوي الإشعارات على أي نص من الرسالة، بل تعرض فقط عبارات مثل: *"لديك رسالة جديدة..."* أو *"شخص ما خصّص لك بعض الكلمات."* وتفتح صفحة البريد الوارد عند النقر عليها.

## ٤. التثبيت والتشغيل محلياً

### ١) تثبيت الحزم
```bash
npm install
```

### ٢) إعداد المتغيرات البيئية
انسخ ملف `.env.example` إلى `.env` وحدّث القيم:
```bash
cp .env.example .env
```
لتوليد مفاتيح VAPID لإشعارات Web Push (اختياري):
```bash
npx web-push generate-vapid-keys
```

### ٣) دفع مخطط قاعدة البيانات إلى PostgreSQL
```bash
npx drizzle-kit push
```

### ٤) تشغيل المشروع
```bash
npm run dev
```

### ٥) تشغيل المهام المجدولة في الإنتاج (Cron)
يمكنك جدولة طلب دوري كل دقيقة إلى:
`GET /api/dispatch` مع ترويسة `Authorization: Bearer YOUR_CRON_SECRET`
لتوصيل الرسائل المؤجلة وإرسال إشعارات Push حتى عندما لا يكون المستخدم فاتحاً للتطبيق (كما يعمل تلقائياً عند كل زيارة أو تحديث داخل التطبيق).

## ٥. اختبار الخصوصية والتوصيل بحسابين

1. افتح نافذة متصفح عادية وأنشئ **الحساب الأول** عبر `/register`، ثم انسخ رمز الدعوة من `/connect`.
2. افتح نافذة متصفح خفية (Incognito) وأنشئ **الحساب الثاني** عبر `/register`، وأدخل رمز الدعوة في `/connect`.
3. حاول إنشاء حساب ثالث وإدخال نفس الرمز — سيرفض الخادم الطلب لأن العلاقة قد اكتملت لشخصين فقط.
4. أرسل رسالة من الحساب الأول بمدة توصيل (مثلاً 5 دقائق) — ستظهر في صندوق الوارد للحساب الثاني بحالة *"في الطريق إليك..."* ولن يعيد الخادم محتواها إلا بعد مرور المدة على ساعة الخادم.
